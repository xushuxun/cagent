# 公告文件库（lakehouse）存储规范

本仓库 `lakehouse/` 与数据目录是两回事，别混：

| 位置 | 内容 | 谁在用 |
|---|---|---|
| 数据目录 `<仓库根>/.cagent/`（默认 lakehouse 根，可被参数覆盖） | 公告本体：原始 PDF 与解析产物 | 下载、解析、分析全部环节 |
| 本仓库 `lakehouse/` | 本规范 + 股票池名单 | 批量下载与按名单抓取 |

本文件是数据目录的唯一权威说明：读写它之前先读完，并严格按约定操作。

两层结构，各自幂等、可独立重建：

- **raw 层**：从数据源抓取的原始 PDF，写入后不再修改。损坏时按公告索引里的链接重新下载。
- **derived 层**：解析产物（再生品）。损坏时按 raw 重新解析。
- 同一套 key 布局既用于本地文件系统也用于对象存储（如 `s3://bucket/data/hk/09863/...`），
  约定不依赖本地文件系统特性。

## 目录布局

```
<仓库根>/.cagent/
├── hk/                              # 港股（HKEx 披露易）
│   └── 09863/                       # 每公司一个目录，目录名 = 股票代码
│       ├── index.json               # 公司信息 + 公告元数据
│       ├── 2022-09-20_2022092000456_c.pdf          # raw
│       └── derived/
│           ├── 2022-09-20_2022092000456_c.md       # 解析全文
│           ├── 2022-09-20_2022092000456_c.toc.json # 章节目录（构建产物）
│           └── images/                              # 解析时裁剪出的图，按公告分目录
└── cn/                              # A股（巨潮），同一布局
```

- **市场码**：`hk` = 港股，`cn` = A股。先分市场再分公司，避免跨市场代码撞号。
- **目录名 = 数据源代码原样**：港股 5 位数字（不足前补零，如 `09863`），A股 6 位（如
  `601633`）。
- **数据边界**：港股电子披露始于 2007-06-25，更早的公告不存在于本库。
- 现状规模（本机实测）：`hk` 50 家公司全部已解析；`cn` 5480 家公司，其中 169 家已解析，
  其余只有原始 PDF 与元数据。下载覆盖面由股票池名单决定，解析按需进行。

## 命名规则

- **PDF**：`<ISO日期>_<数据源原文件名>`。日期前缀让列目录即得时间序，不依赖 mtime（对象存储
  的 mtime 不可靠）；原文件名在数据源侧全局唯一，既是去重键也是溯源锚点。扩展名保持数据源
  原样（A股常见大写），读取端不依赖它。港股公告日期是 `DD/MM/YYYY`，入库必须转 ISO。
- **解析全文**：与 PDF 同名，扩展名换成 `.md`，放 derived 层。
- **章节目录**：与解析全文同名，扩展名换成 `.toc.json`。它是构建产物——可由解析全文重生成，
  缺失时下游自动重建，与全文同生命周期。

## 解析全文与页码

正文是公告全文 markdown，页之间用 `<!-- page N -->` 注释分隔：渲染时不可见，程序可提取。
所有页码引用（报告里的 `p.N`）都指这个**物理页号**，不是年报页脚印的印刷页号——两套页码
常年相差若干页，这是页码类错误的最大来源。

## index.json（每公司一份，raw 层清单）

外层固定四项：市场、代码、公司名、公告清单。清单里每条公告：

| 字段 | 含义 | 港股 | A股 |
|---|---|---|---|
| 日期 | 公告日期，ISO 格式 | `date` | `announcementDate` |
| 标题 | 公告标题 | `title` | `title` |
| 文件名 | 对应 raw 文件名 | `file` | `file` |
| 链接 | 数据源原始链接（溯源用） | `link` | `link` |
| 类型 / 大小 | 文件类型与体积 | `fileType` / `fileSize`（字符串） | 同名，大小为数字 |
| 代码 / 名称 | 数据源侧的证券代码与简称 | 无 | `secCode` / `secName` |

- **已知偏差**：A股清单用 `announcementDate` 而非规范的 `date`，体积是数字而非字符串，
  覆盖全部 A股公司目录。新写入请按规范用 `date`。
- 读取端以 derived 层的文件名为准排序，日期取不到时回落到文件名前 10 个字符、标题取不到时
  用文件名。因此清单顺序只依赖文件名前缀，上述字段缺失不影响顺序，只影响展示信息。
- 清单按日期升序；编码 UTF-8，不转义非 ASCII 字符。

## 常用查询

| 需求 | 做法 |
|---|---|
| 某公司全部公告（按时间排序） | 读该公司 `index.json` 的公告清单 |
| 某公司全部解析产物 | 列 derived 层的 markdown，按文件名排序 |
| 待解析队列 | 清单里的文件名减去 derived 层已有的同名产物 |
| 遍历所有公司 | 列市场目录下的子目录 |

## 写入协议

**新公告入 raw：** ① 取元数据里的原文件名，与公司目录已有文件比对，已存在则跳过（去重）；
② PDF 写入 `<市场>/<代码>/<ISO日期>_<原文件名>`；③ 更新 index.json，追加条目、保持按日期
升序、字段按上表写全。

**解析结果入 derived：** ① 写入 `<市场>/<代码>/derived/<与PDF同名>.md`，已存在直接覆盖；
② 不回写 index.json（derived 层自描述）。
