# AI 投研框架访谈对本项目的启示

> 来源：`docs/ai_investment_research_framework.md`（System2 创始人 Matei Zatreanu、前 Citadel PM Brett Caughran 两篇、前 Tiger Global PM Joe O'Donnell 的访谈/演讲精编）。
> 记录日期：2026-09-07。只记对本项目有用的结论，细节见原文。

## 外部验证：与本项目设计一致的共识

1. **数字的唯一出处必须是结构化数据，模型只负责解释。**
   LLM 直接从 PDF/网络抓数字必然出错（"没有数据就把份额设成一样"、"从博客抄 EPS"）。
   正确架构是「数据层 → 情报层 → Agent 层」；数字经程序计算，模型只做判断。
   → 对应本项目"数字表是唯一数字来源、估值表格程序渲染、模型只出折扣率"。

2. **双层验证：机器全面查 + 人盯关键变量。**
   机器交叉核对数字、来源、单位、公式；人围绕投资逻辑回原始资料核验 15–20 项关键变量
   （"97% 正确但正负号错、漏 2 亿利息"，错误会继续传导到下游指标）。
   → 对应本项目恒等式校验、上界对账、[对账] 环节。

3. **来源优先级 + 失败必须报警，不得静默降级。**
   首选来源失败时停止或报错，不能悄悄改用低质量来源；系统必须证明用了正确版本和正确来源。
   → 对应本项目"检出一律披露、未检出 ≠ 无异常"。

4. **机械任务自动化，判断留给人。**
   AI 先做：资料整理、指引兑现追踪、管理层历史言行对比、黑线比较、重复性检查；
   不直接产出交易/投资结论。
   → 对应本项目"数字表程序算、报告只搬运"。

5. **摘要会丢信息，完整感是危险的。**
   流畅的摘要让读者更自信但掌握的信息反而更少；语气、限定条件、矛盾最先被丢掉。
   → 本项目让模型读原文章节并带页码引用，而非只喂摘要，方向正确。

## 值得借鉴的新做法

6. **黑线比较（year-over-year diff）**：今年年报 vs 去年年报，只让模型找"所有重要变化"。成本低，可加进定性环节。
7. **指引兑现追踪**：回溯多年管理层指引 vs 实际结果，做管理层可信度档案。比单次叙事更能暴露盈利质量问题，适合并入 [定性] 或估值的盈利质量对账。
8. **管理层研究拆成多个 Skills**：内部人交易、CEO/CFO 措辞差异、承诺兑现、回购效果、会计调整，各成一项再汇总。比一个大 prompt 质量高。
9. **错误样例回写规则**：真实错误反馈进 Skill/规则文件，循环迭代（"技能文件的质量来自循环，不来自第一版写得多漂亮"）。→ 对应本项目"积累 LLM 评估样例进 cagent/tests"，应坚持。
10. **闭卷检验作为完成标准**：不看资料能否说清"一美元收入如何变成现金、三个关键驱动、两个核心风险、预期差在哪"。可作为报告验收的补充标准。
11. **研究分层、前端闸门**：快速概览 → 筛查 → 完整覆盖，容错率不同（初筛可错、持仓跟踪不可错）。将来若扩展股票池筛选，这是现成框架。

## 警示（防系统腐化）

12. **回音室风险**：模型会迎合使用者偏好，"完全符合我的标准"的叙事最可疑。机械防线（数字核对、页码可回查）是对冲手段，不能省。
13. **效率不能以牺牲理解为代价**：目标不是 10 小时压成 1 小时，而是省下的时间投向更深的验证。避免为出报告而出报告。
14. **工程脚手架快速折旧，流程与数据架构是耐久资产**：少在提示词技巧/中间态缓存上投入，多把研究流程写成明确规则。→ 对应本项目"文档记原则、环节中间态不落盘"。
