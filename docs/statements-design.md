# 财报阅读的启发式设计

人读报表时，并不是逐行翻译，也不是先背一套科目 ID，而是在同时利用几类证据：

1. **先看整体结构**

   先确认这是合并还是母公司报表、哪一列是本期、币种和单位是什么，再看“流动资产”“非流动资产”等区域如何衔接。

2. **利用版面理解层级**

   标题、缩进、空行、分节、续页、合计行、“其中”位置共同表达结构。人知道“其中”只是局部展开，不会把它再次加入上级合计。

3. **按呈现方式理解符号**

   人不会简单认为费用永远为负：
   - A 股常以正数列示营业成本，再由“减”表达方向；
   - 港股可能直接以括号负数列示；
   - 财务费用本身还可能为负。
   
   方向由名称、上下文、金额符号和公式共同决定。

4. **用算术检验理解**

   人看到合计时会尝试加总；对不上就回查是否漏行、重复、看错列或误读单位。算术是理解的反馈，而不是最后一步才发现问题。

5. **利用跨页和附注补充上下文**

   例如主表没有单位时，人会去附注找“均以人民币千元为单位”，不会仅凭金额大小猜测。

AI agent 错漏多，主要是当前流程破坏了这些证据：

- HTML 转文本后，视觉层级和续页关系变弱。
- 模型一次要同时抄数、建树、判符号、映射科目和生成公式，任务过多。
- few-shot 太短或与真实输入不同构，模型学会只输出核心行。
- 等式由模型生成后缺少可靠的算术回验，或者错误发生后没有区分是提取错误还是校验错误。
- 同名科目仅靠名称定位，容易跨层级误选。
- 重试从头生成，容易修一处、坏另一处。

因此更好的方案应尽量还原人的阅读过程：

- 保留完整页面、原序和跨页上下文；
- 先明确报表口径、年度、币种、单位；
- 再按区域和层级建树；
- 每个节点保留原始行证据；
- 校验 agent 负责理解归并关系，程序负责计算；
- 错误按“漏行、错列、错单位、错层级、错符号、错公式”分类反馈；
- 修改只作用于相关分支，之后重新校验整表。

**人之所以可靠，不是因为人不会算错，而是人会在结构、语义和算术之间反复核对。agent 也需要这个闭环。**
