# PRD — 财务报表阅读器

## 产品目标

把原始年报变成一张**可交互阅读的合并报表**：读者看任何一行数字，一键跳到它的来源页、对应会计政策、报表项目附注和历年同项数据。替读者省掉在几百页 PDF 里来回翻找的时间。

第一原则：让读者更快、更准地拿到报表背后的信息，还是只让系统更复杂？不服务这个目标的展示、校验、抽象都不做。

## 用户与场景

- 读者：第一次看这家公司年报的个人投资者或研究员，需要快速读懂合并报表并追溯每个项目。
- 典型场景：看到"存货"金额异常 → 点一下 → 看到存货附注（构成、跌价准备）、存货会计政策、历年存货走势、原年报页。

## 范围（In Scope）

### 数据层（从现有 derived 产物提取，不重新 OCR）

1. **主表提取**：从 `.cagent/` 的 markdown（`<!-- page N -->` 分页）中提取合并资产负债表、合并利润表、合并现金流量表，解析为结构化数据：科目名、附注编号、当期金额数值。合并报表为主，母公司报表只作附件。
   - 权益变动表本期不做：读者最少看、版式最复杂的一张，先保证三大报表体验，后续有真实需求再加。
2. **附注关联**：用 `.tables.json` 原表索引定位报表项目附注（存货、固定资产、应收款项等分项目附注表），建立 科目 → 附注表 → 页号 的映射。
3. **会计政策定位**：从"重要会计政策及会计估计"章节提取各政策条目，建立 政策 → 覆盖科目 的映射（如"存货跌价准备"政策 → 存货科目）。
4. **多年对齐**：同一科目跨年度对齐（按科目名归一，页号各自保留），供历年对比展示。

### Web 展示层（新增 Flask 应用，风格对齐 `cagent/trace/server.py`）

- **报表视图**：三张合并报表渲染成一页网页，每行科目可点击。金额单位换算与原文坐标核验由程序完成。
- **原地联动（核心交互）**：鼠标点击科目行，关联信息直接展开在报表页面内（侧栏或行下展开），**不做页面跳转**：
  - 会计政策原文（带页码标注，随附注同屏展示）；
  - 报表项目附注表（结构化展示，带页码）；
  - 历年同项金额小图/表；
  - 原年报对应段落的文本引用（标注物理页号，作为展示内容的一部分，不离开报表页）。
- **原文查看器**：独立页面按页渲染 markdown 原文，与报表视图互相跳转（报表联动面板中给原文页链接），属于补充入口而非主路径。
- 入口：`uv run python -m cagent.report.server --stock 601633 --market cn`。

## 范围外（Out of Scope）

- 不做分析、比率计算、结论与判断——那是 wiki 报告的职责，本产品是阅读器。
- 不做扫描版 PDF 的表格结构重建（OCR 产物之外的版式还原）；OCR 已解析出的表格直接用，解析失败的单元格显示原文页号让用户自己看。
- 不做用户系统、多公司对比、移动端适配。

## 关键设计约束

- 每个数字必须带物理页号（`<!-- page N -->` 口径），点击可达原文。
- 表格定位、科目与当期单元格选择等理解活交给模型且在 trace 记账；程序负责单元格编号、直读数值和原文核验，不做恒等式检测。
- 全部读取现有 lakehouse 产物，幂等：产物已存在则跳过，`--force` 覆盖。
- 沿用项目存储规范（`lakehouse/README.md`），新产物命名 `statements.json` / `notes_map.json` 存 derived 层。

## 验收

1. 对至少一只 A 股 + 一只港股，三张合并主表结构化提取完整，合计行与原文能对平（或明确标注不平处）。
2. 点击任一科目，会计政策、项目附注、历年数据、原文引用（带页号）在报表页内原地展开，无需跳转。
3. 原文查看器与报表视图双向跳转可用；每个展示数字页码可溯源。
